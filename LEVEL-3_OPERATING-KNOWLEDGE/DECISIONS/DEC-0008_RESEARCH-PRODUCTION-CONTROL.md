# DEC-0008 연구·견적·생산 제어 경계

- 상태: REVIEW
- 제안일: 2026-07-23
- 결정자: CEO·연구 책임자 검토 필요

## 배경

GP Workbench에는 문의, 원료, 레시피 연구, 정밀 견적, 생산 스케쥴, LOT와 생산 문서가
연결되어 있지만 Company OS에는 이 상태 흐름과 시스템별 원본 경계가 충분히 기록되어
있지 않다. Hub는 R&D 저장소를 예정으로 설명하고 있어 현재 Workbench 실행과도 차이가 있다.

정책과 실제 운영 기록을 구분하지 않으면 Workbench 구현이 사실상의 정책이 되거나, 반대로
문서 동기화가 실제 연구·생산 데이터를 손상시킬 수 있다.

## 제안 결정

1. Company OS는 연구·견적·생산의 정책, 상태 전환, 승인과 보안 원칙의 원본으로 한다.
2. GP Workbench는 문의·원료·레시피·견적·스케쥴·LOT의 실행 기록과 감사 로그를 관리한다.
3. Hub는 B2B 파이프라인, 견적 표준, Agent 운영 스펙과 보안 저장소 경로 인덱스를 관리한다.
4. 실제 발행 문서, 고객별 원본, 생산단가표와 시험성적서는 승인된 보안 저장소에서 관리한다.
5. 신규 레시피는 연구중으로 시작하고 명시적 확정 후에만 정밀 견적과 생산 준비에 사용한다.
6. 레시피 확정은 동일 레시피의 생산 스케쥴을 한 건만 생성해야 한다.
7. 수주 또는 LOT가 연결된 레시피는 단순 확정 취소하지 않고 승인된 정정 절차를 따른다.
8. 실제 고객·처방·원가 데이터는 공개 저장소, Slack, Preview와 스크린샷에 노출하지 않는다.
9. 다른 운영 기록이 참조하는 레시피·원료·스케쥴·LOT는 하드 삭제하지 않고, 참조 검증과
   승인된 보존·정정 절차를 적용한다.

## 이번 결정에서 확정하지 않는 항목

- 제형별 공식 MOQ
- 최소 마진과 목표 원가
- 샘플 개발비와 공제·환급 기준
- 고객 결제조건
- 제품별 시험·검사 기준과 시험성적서 재사용 범위
- R&D Agent의 자동 실행 권한

위 항목은 근거자료와 책임자 검토 후 별도 Decision으로 확정한다.

## 승인 시 필요한 후속 작업

1. `RND.md`, `PRODUCTION.md`와 `SOP-010`을 ACTIVE 기준으로 검토한다.
2. Hub의 R&D·Workbench 프로젝트 설명과 견적 표준을 동기화한다.
3. Workbench `.gp-company-os.yaml`에 승인된 OS revision과 Decision을 반영한다.
4. 운영 데이터 무결성과 백업을 비식별·읽기 전용으로 검증한다.
5. 결제·MOQ·시험 근거 충돌은 별도 CEO Decision까지 자동 변경하지 않는다.
